# نورث‌ویند — فروشگاهِ آنلاینِ نرم‌افزارِ سازمانی (Blazor WebAssembly + ASP.NET Core + SQLite)

یک فروشگاهِ کاملِ فول‌استک برای فروشِ مجموعهٔ نرم‌افزارِ ERP/کسب‌وکار به مشتریانِ
سازمانی (B2B) و شخصی (B2C). رابط به فارسی، کاملاً راست‌به‌چپ، تاریخ‌های جلالی و
قیمت‌ها به **تومان**؛ با پایگاه‌دادهٔ واقعی و مانا (SQLite) و seedِ واقع‌گرایانه در
نخستین اجرا.

---

## ۱. ساختار (چهار لایه)

```
Aria/                             چهار پروژه = چهار لایه
├── Client/Northwind.Client/      ① کلاینت — Blazor WebAssembly
│   ├── Pages/                    فروشگاه، پورتالِ مشتری، پنلِ مدیریت
│   ├── Components/               کامپوننت‌های رابط (Layout · Store · UI)
│   ├── Services/                 وضعیت + کلاینتِ تایپ‌دارِ API
│   ├── Contracts/                DTOهایِ سیم (فقط سمتِ کلاینت)
│   └── wwwroot/css/tokens.css    نشانه‌های طراحی
│
├── Server/Northwind.Core/        ② هسته — منطقِ کاری
│   ├── Services/                 سفارش، لایسنس، کاتالوگ، پشتیبانی…
│   ├── Models/                   مدل‌هایِ ورودی/خروجیِ API
│   └── Mapping/                  نگاشتِ موجودیت → مدل
│
├── Server/Northwind.Api/         ③ API — کنترلرها + نقطهٔ اجرا
│   ├── Controllers/              ۸۴ مسیرِ REST روی /api/v1
│   ├── Middleware/               خطاهایِ دامنه → پاسخِ یکسانِ JSON
│   ├── Program.cs                سیم‌کشیِ لایه‌ها
│   └── data/                     northwind-api.db
│
├── Server/Northwind.Data/        ④ داده — پایگاه‌داده
│   ├── Entities/ · Enums/        ۲۷ موجودیت
│   ├── Persistence/              DbContext، نگاشت‌ها، DatabaseOptions
│   └── Migrations/               مهاجرت‌هایِ EF
│
└── Aria.sln
```

**قاعدهٔ وابستگی تک‌جهته است:** `Api → Core → Data` و کلاینت فقط از راهِ HTTP.
هیچ لایه‌ای از لایهٔ بالاتر خبر ندارد و این قاعده با `ProjectReference` اجبار شده است.
توضیحِ کامل، الگوها و چک‌لیستِ افزودنِ قابلیت: [`Server/ARCHITECTURE.md`](Server/ARCHITECTURE.md).

داده پشتِ اینترفیسِ `IStoreApi` است. پیاده‌سازیِ پیش‌فرض `StoreApiRouter` است که
همهٔ کارها را روی `/api/v1` انجام می‌دهد؛ برایِ کارِ بدونِ سرور می‌توانید در
`Client/Northwind.Client/Program.cs` آن را با `MockStoreApi` عوض کنید — بدونِ
دست‌زدن به یک خط از صفحه‌ها.

**فقط یک API وجود دارد.** API قدیمیِ `/api/...` در موجِ ۴ کامل حذف شد؛ جزئیات:
[`Server/CLIENT-V1.md`](Server/CLIENT-V1.md).

## ۲. اجرا

### ویندوز — یک کلیک، یک پورت (پیشنهادی)

```bat
start-windows.cmd
```

کلاینت را Release منتشر می‌کند و API را روی **http://localhost:5182** بالا می‌آورد؛
مرورگر خودش باز می‌شود. فقط **یک** پروسه لازم است — نه پنجرهٔ دوم، نه CORS، نه
تنظیمِ نشانیِ API.

### خط فرمان — فقط API، بدونِ هیچ اسکریپتی

```bash
dotnet build Aria.sln                            # یک‌بار: کلاینت هم بیلد می‌شود
dotnet run --project Server/Northwind.Api        # http://localhost:5182
```

API خودش سایت را هم سرو می‌کند: اگر `ASPNETCORE_WEBROOT` ست نشده باشد،
`Client/Northwind.Client/wwwroot` را به‌عنوانِ ریشهٔ فایل‌هایِ استاتیک می‌گیرد و
`_framework` را از خروجیِ بیلدِ کلاینت. پس با **یک** دستور، هم رابط و هم API
رویِ یک نشانی بالا می‌آید. (Swagger: `/swagger`)

> اگر کلاینت بیلد نشده باشد، لاگِ سرور صریح هشدار می‌دهد؛ چون لایهٔ API عمداً به
> پروژهٔ کلاینت ارجاع نمی‌دهد (قاعدهٔ وابستگیِ تک‌جهته در `Server/ARCHITECTURE.md`).

### حالتِ توسعه — کلاینت و سرور جدا

```bat
اجرای-همه.bat        :: دو پنجره: API روی ۵۱۸۲ و کلاینت روی ۵۲۱۲
```

یا دستی، در دو ترمینال:

```bash
dotnet run --project Server/Northwind.Api        # 5182
dotnet run --project Client/Northwind.Client     # 5212
```

نشانیِ API در `Client/Northwind.Client/wwwroot/appsettings.json` تعیین می‌شود
(پیش‌فرض `http://localhost:5182/`). اگر پورتِ سرور را عوض کردید، همان مقدار را
هم‌اهنگ کنید.

پایگاه‌داده در `Server/Northwind.Api/data/northwind-api.db` ساخته و پُر می‌شود.
برای بازسازی از صفر، فایل‌های `northwind-api.db*` را پاک کنید و دوباره اجرا کنید.

### داده‌ها کجا ذخیره می‌شوند؟ (و چرا ناپدید نمی‌شوند)

هر چیزی که در پنل می‌سازید — محصول، دسته، مقاله، سفارش، کاربر — در همان
لحظه در فایلِ پایگاه‌داده نوشته می‌شود و همهٔ صفحه‌ها آن را از پایگاه‌داده
می‌خوانند؛ هیچ فهرستی در حافظه یا به‌صورتِ دادهٔ نمایشیِ بازتولیدشده نگه داشته
نمی‌شود.

- **مسیرِ فایل** در نخستین خط‌های اجرایِ سرور چاپ می‌شود:
  `رشتهٔ اتصالِ SQL Server تنظیم نشده — حالتِ نمایشی رویِ SQLite: …/data/northwind-api.db`
  و بلافاصله پس از آن:
  `فایلِ پایگاه‌داده از پیش موجود بود …` و `پایگاه‌داده آماده است — N محصول از فایل خوانده شد.`
  اگر آن `N` پس از هر راه‌اندازی صفر بود، یعنی مسیرِ فایل عوض شده است.
- **مسیرِ پیش‌فرض پایدار است**: مسیرهایِ نسبی هرگز داخلِ `bin/`، `obj/` یا
  `publish/` نمی‌افتند (چون `Clean`/`Rebuild` آن پوشه‌ها را پاک می‌کند و داده
  با آن‌ها می‌رفت). ریشهٔ داده پوشهٔ پروژه است، نه پوشهٔ ساخت.
- **جایِ دلخواه**: متغیرِ محیطیِ `ARIA_DB_PATH` را به مسیرِ کاملِ فایل بدهید تا
  پایگاه‌داده هر جایِ دیگری (مثلاً بیرون از مخزن) نگه داشته شود:
  `ARIA_DB_PATH=D:/AriaData/northwind.db dotnet run --project Server/Northwind.Api`
- **پشتیبان‌گیری**: هنگامِ خاموش‌بودنِ سرور، `northwind-api.db` را کپی کنید.
  SQLite ممکن است دو فایلِ کنارِ آن هم داشته باشد (`-wal` و `-shm`)؛ اگر سرور
  روشن است، هر سه را با هم کپی کنید.
- **پایگاه‌دادهٔ واقعی**: برایِ SQL Server، بخشِ `Database` را از
  `appsettings.SqlServer.Example.json` به `appsettings.json` ببرید؛ در آن حالت
  داده در خودِ SQL Server است و مهاجرت‌ها هنگامِ شروع اعمال می‌شوند.

برایِ دیدنِ همین اطلاعات از داخلِ سایت: **پنلِ مدیر ← تنظیمات** — کارتِ
«پایگاه‌دادهٔ سرور» نوع، مسیرِ فایل، حجم و شمارِ محصول/دسته/کاربر/سفارش/لایسنس
را مستقیم از پایگاه‌داده نشان می‌دهد (نقطهٔ پایانیِ
`GET /api/v1/admin/system/database`).

### اسکریپتهایِ تک‌پورتی (لینوکس/مک و پیش‌نمایشِ ابری)

```bash
bash start-preview.sh    # انتشارِ کلاینت + اجرا روی 0.0.0.0:5210
bash start-server.sh     # فقط API روی 0.0.0.0:5211
```

## ۶٫۱. مدیریتِ خطاها (سرور ← کلاینت ← کاربر)

همهٔ خطاها یک شکل دارند و از یک مسیر می‌آیند؛ هیچ‌جایِ API صفحهٔ HTML، متنِ
انگلیسیِ چارچوب یا استک‌تریس برنمی‌گرداند.

```json
{
  "code": "validation_failed",
  "message": "برخی از فیلدها معتبر نیستند.",
  "status": 400,
  "errors": { "email": ["ایمیل لازم است."] },
  "traceId": "0HNQD3USGJIQS:00000001"
}
```

| وضعیت | کِی رخ می‌دهد | کد | چه کسی نشان می‌دهد |
|---|---|---|---|
| ۴۰۰ | بدنه یا پرس‌وجویِ نامعتبر | `validation_failed` / `invalid_json` / `invalid_request` | پیامِ فیلدها در Toast و بنرِ خطا |
| ۴۰۱ | بدونِ توکن یا توکنِ منقضی | `unauthorized` | بنر + دکمهٔ «ورود به حساب» (برایِ مهمان، دروازهٔ ورود خودش هدایت می‌کند) |
| ۴۰۳ | نقشِ کاربر اجازه ندارد | `forbidden` | بنر: «به این بخش دسترسی ندارید.» |
| ۴۰۴ | شناسه یا نشانیِ ناموجود | `not_found` | صفحهٔ «پیدا نشد» خودِ صفحه (بنر نشان داده نمی‌شود) |
| ۴۰۹ | تناقض/تکرار/تضادِ هم‌زمانی | `conflict` / `concurrency_conflict` | بنر |
| ۴۱۵ | قالبِ محتوا پشتیبانی نمی‌شود | `unsupported_media_type` | بنر |
| ۴۲۲ | قاعدهٔ کسب‌وکار (مثلِ ورودِ ناموفق) | `business_rule` / `invalid_credentials` | Toast صفحه + بنر |
| ۵۰۰ | خطایِ پیش‌بینی‌نشده | `server_error` | بنر با متنِ فارسی و `traceId` بدونِ هیچ جزئیاتِ داخلی |

- **سرور**: `ApiExceptionMiddleware` همهٔ استثناها (دامنه، احراز، JSONِ خراب،
  پایگاه‌داده، ناشناخته) و کدهایِ وضعیتیِ بی‌بدنه (۴۰۱/۴۰۳/۴۰۵/۴۱۵) را به همان
  قرارداد تبدیل می‌کند؛ `SuppressMapClientErrors` جلویِ `ProblemDetails`
  انگلیسیِ چارچوب را می‌گیرد؛ نشانیِ ناشناخته زیرِ `/api` می‌شود ۴۰۴ JSON
  (نه صفحهٔ اصلی). هر پاسخ هدرِ `X-Trace-Id` دارد.
- **پیام‌هایِ اعتبارسنجی**: اتریبیوت‌هایِ بدونِ پیامِ فارسی (مثلِ `[Range]`)
  با `ErrorText` به فارسیِ روشن برگردانده می‌شوند.
- **کلاینت**: `V1Api` پیام و کد و `traceId` را از پاسخ می‌خواند و در
  `ApiErrorState` می‌گذارد؛ `ApiErrorBanner` (در هر دو چیدمان) آن را با عنوانِ
  فارسی، کدِ ماشین‌خوان و کدِ پیگیری نشان می‌دهد. خطاهایِ نوشتن هم‌زمان در
  `Toast` صفحه می‌آیند. `ErrorBoundary` در `App.razor` خطاهایِ خودِ رابط را
  به کارتِ «خطایی رخ داد + تلاشِ دوباره» تبدیل می‌کند.
- **آزمودنِ مسیرِ ۵۰۰** در محیطِ توسعه: `GET /api/v1/_diag/boom`.

## ۷. کارهای باقی‌مانده (در صورت نیازِ شما)

1. **احرازِ هویتِ واقعی**: سرور اکنون از هدرِ سادهٔ `X-User-Id` استفاده می‌کند.
   جایگزینی با JWT + Refresh Tokenِ چرخان و رمزنگاریِ scrypt توصیه می‌شود.
2. **تست**: پروژه تستِ خودکار ندارد.
3. **مهاجرت (Migrations)**: دیتابیس با `EnsureCreated` ساخته می‌شود؛ برای
   تغییراتِ بعدیِ طرح، `dotnet ef migrations add` لازم است.
4. **محدودسازیِ نرخ** و قفل‌شدنِ حساب پس از تلاش‌های ناموفق پیاده‌سازی نشده است.
